# Rhythm Forge 1.0.15 loader review

Base: `3931d985dbe207e3fbc321c0f8adea4ee288ae43` (1.0.14).
Work branch: `codex/youtube-loader-recovery`.

## Findings and changes

1. The previous loader ignored ambient yt-dlp configuration and did not enable
   Node.js explicitly. yt-dlp enables only Deno by default. Both metadata and
   media requests now use the same options and a shared, bounded runtime probe:
   Deno 2.3+ first, Node.js 22+ second. The dependency checker uses the same probe
   and checks EJS package presence for an Arch-owned yt-dlp executable.
2. Warnings needed to distinguish missing challenge solvers, PO tokens and
   verification were suppressed. The loader now classifies the bounded output
   into actionable messages. It does not show arbitrary service output that
   could contain signed URLs or session tokens. Verification errors outrank
   incidental skipped-format warnings.
3. A failed download/merge could leave `track.f137.mp4` or `track.f140.m4a`.
   The old cache lookup accepted these as finished tracks. Lookup now accepts
   only final `track.<video extension>` names and ignores empty files and split
   streams, allowing a later download to resume rather than analyze a fragment.
4. The GTK setup screen offers an explicit **Browser session** selector for
   permitted signed-in requests. It defaults to none, is disabled during loads,
   and is not persisted. The same selection is used for metadata and media.
5. Version numbers are updated together. The README explains setup and recovery.
   GitHub Actions now runs regression tests, real GTK smoke tests under Xvfb,
   Python/shell syntax checks and ShellCheck. CI requires GTK tests to execute.

`--ignore-config`, URL argument separation, process-group cancellation, absolute
deadlines and existing output/media limits remain. No automatic runtime/package
installation, cookie export, token service or remote EJS code fetch was added.
Locally installed yt-dlp provider plugins remain governed by its normal plugin
discovery; plugin-specific configuration is not silently imported.

## Validation scope

Local unittest discovery: 69 tests, 67 passed and 2 GTK tests skipped because
GTK/display support is absent in the local container. Tests run real temporary
runtime and downloader executables through the bounded process runner; only the
GTK boundary and expensive audio analysis are replaced in loader tests.
Coverage includes runtime versions/fallbacks, opt-in session arguments on both
requests, metadata and download errors, retry after partial output, cache reuse,
invalid metadata/durations and cancellation. The existing Qt 6, process-boundary,
gameplay and progression tests remain included.

Python compilation, Bash syntax, ShellCheck 0.10.0 and `git diff --check` pass.
The real yt-dlp 2026.08.19 parser (upstream commit
`3a08beaf031ab68f966401ead017ac81fe8486cf`) accepts the new options. An offline
control with invalid ambient configuration fails, while the loader options
ignore it and successfully list extractors.

The corresponding PR links the final commit's CI result. Native Omarchy plugin
validation, Wayland playback and a live YouTube download have not been run in
this container. These changes fix demonstrated integration defects; they do not
prove the exact cause of every intermittent failure on the user's machine or
guarantee access through YouTube verification, account, regional or PO-token
restrictions.
